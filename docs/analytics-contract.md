# Echora Analytics Service Contract

This document specifies the API contracts, message schemas, and integration points for `analytics-service`.

---

## 1. POST /api/analytics/events

Direct endpoint called by client applications (web/mobile) to record user interactions.

- **URL**: `/api/analytics/events`
- **Method**: `POST`
- **Content-Type**: `application/json`
- **Success Status**: `202 Accepted` (no response body)
- **Failure Status**: 
  - `400 Bad Request` (Bean Validation failure)
  - `503 Service Unavailable` (Message broker unavailable)

### 1.1 Request Body Specification

| Field | Type | Required | Constraints | Description |
|---|---|---|---|---|
| `eventType` | String | Yes | `SCAN`, `AUDIO_PLAY` | Type of user interaction. |
| `poiId` | Long | Yes | Positive integer (> 0) | Identifier of the POI. |
| `languageCode` | String | Yes | `vi`, `en`, `ja`, `ko` | Language of the audio or client interface. |
| `triggerType` | String | Conditional | `QR`, `GPS`, `MANUAL` | **Required** when `eventType == "SCAN"`. Optional for `AUDIO_PLAY`. |
| `completed` | Boolean | Optional | `true`, `false` | Audio completion flag. Defaults to `false` when `eventType == "AUDIO_PLAY"` and omitted. |
| `sessionId` | String | Optional | Max 64 chars, regex `^[A-Za-z0-9-_]*$` | Client anonymous session identifier. |

> **Privacy Note**: No IP address or user-identifiable information is accepted or persisted.

### 1.2 Request Examples

#### Scan Event via QR Code
```json
{
  "eventType": "SCAN",
  "poiId": 1,
  "languageCode": "vi",
  "triggerType": "QR",
  "sessionId": "sess-abc-123_456"
}
```

#### Audio Play Event
```json
{
  "eventType": "AUDIO_PLAY",
  "poiId": 1,
  "languageCode": "en",
  "completed": true,
  "sessionId": "sess-abc-123_456"
}
```

### 1.3 Validation Error Response (400 Bad Request)

```json
{
  "timestamp": "2026-10-05T10:00:00",
  "status": 400,
  "error": "Bad Request",
  "message": "Validation failed for one or more fields",
  "fieldErrors": {
    "triggerType": "triggerType is required for SCAN and must be QR, GPS, or MANUAL",
    "languageCode": "languageCode must be one of: vi, en, ja, ko"
  }
}
```

### 1.4 Broker Failure Response (503 Service Unavailable)

```json
{
  "timestamp": "2026-10-05T10:00:00",
  "status": 503,
  "error": "Service Unavailable",
  "message": "Service is temporarily unable to process event due to message broker unavailability"
}
```

## 2. RabbitMQ Message Schema

`analytics-service` declares and manages its own messaging topology.

### 2.1 Topology

- **Exchange**: `saigonvoice.analytics` (Type: `topic`, durable: `true`)
- **Routing Key**: `analytics.event`
- **Queue**: `analytics.event.queue` (Durable: `true`, DLX: `saigonvoice.analytics.dlx`, DLQ routing key: `analytics.event.dlq`)
- **Dead Letter Exchange (DLX)**: `saigonvoice.analytics.dlx` (Type: `direct`, durable: `true`)
- **Dead Letter Queue (DLQ)**: `analytics.event.dlq` (Durable: `true`)

### 2.2 Event Message Payload

Serialized as JSON using Spring AMQP `Jackson2JsonMessageConverter` with inferred type mapping:

```json
{
  "eventId": "a1b2c3d4-e5f6-7890-abcd-ef1234567890",
  "eventType": "SCAN",
  "poiId": 1,
  "languageCode": "vi",
  "triggerType": "QR",
  "completed": null,
  "sessionId": "sess-abc-123_456",
  "occurredAt": "2026-10-05T10:00:00.123"
}
```

| Field | Type | Description |
|---|---|---|
| `eventId` | String (UUID) | Generated by the server on event receipt. Unique constraint in DB. |
| `eventType` | String | `SCAN` or `AUDIO_PLAY`. |
| `poiId` | Long | POI ID. |
| `languageCode` | String | `vi`, `en`, `ja`, or `ko`. |
| `triggerType` | String | `QR`, `GPS`, `MANUAL`, or `null`. |
| `completed` | Boolean | `true`, `false`, or `null`. |
| `sessionId` | String | Client anonymous session identifier or `null`. |
| `occurredAt` | LocalDateTime | Server UTC reception timestamp (explicit UTC). |

### 2.3 Consumer Behavior & Idempotency

- The consumer (`@RabbitListener`) reads from `analytics.event.queue`.
- Persists to SQL Server table `dbo.analytics_event`.
- **Idempotency**: If an event with the same `event_id` is processed again (or throws `DataIntegrityViolationException` on unique key constraint violation), the listener logs a warning and acknowledges/skips the message. It is **not** rejected to DLQ.

## 3. GET /api/analytics/summary

Aggregated analytics metrics for administrative dashboards.

- **URL**: `/api/analytics/summary`
- **Method**: `GET`
- **Success Status**: `200 OK`

### 3.1 Response Structure

```json
{
  "totalScans": 150,
  "scansByTrigger": {
    "QR": 120,
    "GPS": 25,
    "MANUAL": 5
  },
  "totalAudioPlays": 80,
  "audioCompleted": 65,
  "playsByLanguage": {
    "vi": 50,
    "en": 20,
    "ja": 10,
    "ko": 0
  },
  "topPois": [
    {
      "poiId": 1,
      "name": "Chợ Bến Thành",
      "scans": 90,
      "plays": 45
    }
  ]
}
```

### 3.2 Content Service Feign Integration

- **Endpoint**: `GET /api/content/pois/{id}?lang=vi` on `CONTENT_SERVICE_URL`
- **Timeout**: 2000ms connect / 2000ms read. Feign retry is disabled (`Retryer.NEVER_RETRY`).
- **In-Memory Cache**: Resolved POI names are cached in-memory with a TTL of 5 minutes. Failed or timed-out calls are also cached (`null` name) to guarantee that an unavailable content service costs at most one timeout per POI per TTL window.
- **Budget Limit**: Total time spent resolving POI names during summary aggregation is capped at a ~3000ms budget. If the budget is exhausted, any remaining POIs will have `name: null` without blocking the summary response.
- **Resilience / Fallback**: If `content-service` is unreachable or returns 404/5xx, `name` is returned as `null` in the POI object; the summary endpoint still succeeds with `200 OK`.
